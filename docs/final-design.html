WebTranslate Chrome 插件 — 最终设计文档

版本：v3.1 (Final)  |  日期：2026-06-03  |  状态：可进入开发阶段

📌 项目定位

WebTranslate 是一款基于大模型 API 的 Chrome 浏览器扩展。用户在浏览任意网页时，点击右下角悬浮按钮即可按需翻译页面内容；翻译按段落分批进行，译文内联展示在原文下方；同时支持将页面打包下载为 Markdown + 图片资源。采用内联模式（译文插入原文下方）和面板模式（右侧滑出面板，原页面零修改）两种翻译方式。

一、manifest.json 骨架

{

  "permissions": ["activeTab", "storage", "downloads", "scripting", "sidePanel"],
  "host_permissions": ["<all_urls>"],
  "background": { "service_worker": "sw.js", "type": "module" },
  "side_panel": { "default_path": "panel.html" },
  "action": { "default_popup": "popup.html" },
  "content_scripts": [{
    "matches": ["http://*/*", "https://*/*"],
    "exclude_matches": ["chrome://*/*", "chrome-extension://*/*"],
    "js": ["content.js"],
    "css": ["content.css"],
    "run_at": "document_end",
    "all_frames": false
  }],
  "web_accessible_resources": [{
    "resources": ["assets/*"],
    "matches": ["<all_urls>"]
  }]
}
• sidePanel 提供面板模式；若浏览器不支持则回退到 popup 或内联模式。
• action.default_popup 作为无网页时的配置入口 + 全局翻译控制。
• run_at: "document_end" 保证 DOM 构建完成后再注入，配合 IntersectionObserver 覆盖 SPA 动态内容。

二、整体架构

2.1 组件职责

层次组件职责运行环境
Content Script BatchCollector IntersectionObserver 监听视口段落；debounce 组批 页面沙箱
StateManager 队列调度、并发控制（默认 3 批）、AbortController map、状态机主控
CacheManager 内存 Map 缓存 + 定时批量刷入 chrome.storage.session
Renderer InlineRenderer（Shadow DOM 注入）或 PanelRenderer（Port 推送）
Service Worker APIProxy 代理批量 API 请求，Adapter 模式，重试退避 后台独立进程（约 30s 空闲后回收）
DownloadManager fetch 图片、JSZip 打包、Data URL 触发下载
ConfigStore 读写 chrome.storage.local

⚠ MV3 Service Worker 非持久化约束：
• AbortController 不可跨 Worker 唤醒存活 → 取消信号由 CS 端 AbortController map 维护。
• 状态机主控逻辑完全放在 Content Script 端 —— CS 随页面生命周期存在，不会被后台回收。
• Worker 端不维护跨请求的有状态上下文，每个批次的处理是无状态的。

2.2 tabId 管理

Content Script 启动时一次性获取 tabId 并缓存，所有向 SW 的消息均携带；SW 反向推送（进度、下载完成等）通过 chrome.tabs.sendMessage(tabId, ...)。

const { id: TAB_ID } = await chrome.tabs.getCurrent();

四、核心机制：视口优先 + 批量合并

4.1 视口优先懒加载

不再一次性扫描全文，改用 IntersectionObserver + 视口优先级：

const observer = new IntersectionObserver((entries) => {
  const needs = entries
    .filter(e => e.isIntersecting && !e.target.dataset.wtDone)
    .map(e => e.target);
  if (needs.length) batchQueue.push(...needs);
}, { rootMargin: "0px 0px 100% 0px" });
  • 第一优先：当前视口内段落 —— 立即进入批量队列
  • 第二优先：视口下方 1 屏 —— rootMargin 预加载
  • 其余内容 —— 用户滚到时 Observer 按需触发
SPA 动态内容：MutationObserver（debounce 500ms）监听新元素 → 自动注册到 IntersectionObserver。L1 DOM 标记 + L2 内容指纹双重去重。

4.2 批量合并请求

多段合并为单次 API 调用，用唯一分隔符拆分响应，解决 N+1 问题。

规则默认值说明
单批总字符数上限≤ 800（可配置）控制 token 消耗和响应时间
单批段落数上限≤ 8防止分隔符解析复杂度过高
单段超长处理≥ 800 字符 → 单独成批长段整体送模型不切分，模型处理长文质量优于人工切碎
收集窗口debounce 100ms等 IntersectionObserver 批量 fire 完再组批

分隔符协议：

───SEP:a1b2c3───
第一段原文
───SEP:d4e5f6───
第二段原文
───SEP:END───

响应解析 + 段数校验：

function parseBatchResponse(raw, items) {
  const parts = raw.split(/───SEP:([a-z0-9]+)───/);
  // 段数校验：返回的分隔符数必须等于请求段数
  const segmentCount = (parts.length - 1) / 2;
  if (segmentCount !== items.length) {
    throw new Error(`Segment mismatch: expected ${items.length}, got ${segmentCount}`);
  }
  const map = {};
  for (let i = 1; i < parts.length - 1; i += 2) {
    map[parts[i]] = parts[i + 1].trim();
  }
  return items.map(item => ({
    id: item.id,
    translation: map[item.fingerprint] ?? item.text
  }));
}
⚠ 分隔符唯一性与安全：
• 分隔符 ID 采用内容 djb2 轻量哈希（前 12 位 hex）+ 随机 2 位，计算性能优于 SHA-256，碰撞概率对 500 条量级缓存可忽略。
• 如果原文包含 ───SEP: 类似文本，构建请求时做 HTML 实体转义，响应解析前还原。
• 解析时顺序配对：按分隔符出现顺序与请求段落顺序一一对应，即使模型在译文中意外生成类似分隔符，影响也仅限于该批次尾部。

五、用户旅程

5.1 首次安装与配置（正常流程）

安装插件→ 右下角出现 🌐 悬浮按钮→ 点击 ⚙️ 设置→ 填写 API URL、模型名、API Key→ 选择默认模式：内联 / 面板→ 测试连接→ 保存到 chrome.storage.local

配置面板居中 Modal。API Key 为 password 类型可一键显隐。即时校验 + 测试连接按钮（发送单字 "hello" 验证 Key），结果以绿/红标签实时反馈。HTTP 地址保存时弹安全警告需二次确认。

5.2 翻译主流程（正常流程）

用户点击 🌐 翻译→ BatchCollector：IntersectionObserver 监听视口段落→ debounce 100ms → 组批（≤800字, ≤8段）→ 查内存缓存 → 命中跳过→ 发送 TRANSLATE_BATCH 到 SW→ SW 代理调用大模型 API→ parseBatchResponse + 段数校验→ Renderer 渲染（内联 Shadow DOM / 面板 Port 推送）

5.3 段落提取策略

  • 目标区域：优先 <article>、<main>；回退 .content、.post；最终回退 document.body。
  • 翻译单元：<p>、<h1>-<h6>、<li>、<td>/<th>、<blockquote>。
  • 排除区域：<nav>、<header>、<footer>、<aside>、[role="complementary"]、广告容器。
  • 保护内容（不翻译）：<pre><code>、行内 <code>、<math>、$$...$$、图片/视频/音频、纯 URL、短数字/时间戳。

5.4 段落去重

层级机制说明
L1：DOM 标记已翻译元素设 data-wt-done="djb2前12位"IntersectionObserver 回调 O(1) 跳过
L2：内容指纹段落文本 djb2 哈希前 12 位 hex，存入内存 Map + chrome.storage.sessionSPA 元素重建后仍可命中；兜底保护

5.5 译文展示

内联模式

<wt-translation data-wt-id="p_1">
  #shadow-root
    <div class="wt-block">
      <div class="wt-header">
        <span class="wt-badge">🌐 译文</span>
        <button class="wt-toggle">折叠</button>
      </div>
      <div class="wt-body">...翻译结果（经 DOMPurify 净化）...</div>

浅色背景 + 左侧蓝色边框。每块独立折叠/展开，折叠状态写入 chrome.storage.session，页面刷新后恢复。

面板模式

panel.html 独立页面渲染双栏（原文 / 译文）或单栏纯译文列表。通过 chrome.runtime.connect 长连接 Port 接收 CS 推送。

5.6 下载页面资源（正常流程）

用户点击 ⬇️ 下载→ CS 生成 Markdown（引入 turndown.js）→ 收集图片 URL 列表→ 发送 {markdown, imageUrls} 到 SW→ SW 逐张 fetch 图片 → JSZip 打包→ Data URL → chrome.downloads.download
Data URL 方案：
zip.generateAsync({ type: "base64" }) → data:application/zip;base64,... → chrome.downloads.download({ url })。无需 revokeObjectURL，无 Blob URL GC 竞态风险。

产物结构：

{page_title}.zip
├── {page_title}.md        ← Markdown（优先取译文，图片链接替换为相对路径）
├── images/
│   ├── image_001.png
│   └── ...
└── metadata.json          ← { source_url, download_time, model, paragraph_count, image_count }

5.7 下载进度反馈

FAB 叠加 SVG 环形进度条：

  • 阶段一：「正在下载图片 8/15」—— SW 每完成一张 fetch，通过 chrome.tabs.sendMessage(tabId, { type:"PROGRESS", stage:"images", current, total }) 推送
  • 阶段二：「打包中...」—— 环形进度动效循环
  • 完成：✅ 2 秒后自动淡出
进度消息防错位：CS 收到 PROGRESS 消息时校验 downloadId 或 timestamp，与当前任务不匹配则忽略（防止页面刷新后新 CS 实例收到旧任务消息）。

八、翻译状态机

IDLE
  │  用户点击翻译
  ▼
SCANNING ── IntersectionObserver 开始监听视口
  │  首批段落进入视口
  ▼
TRANSLATING
  │  BatchCollector debounce 100ms 持续组批
  │  ConcurrencyController 控制并发（默认 3 批同时进行）
  │  每批完成 → Renderer 立即渲染
  │
  ├── 用户点 ⏸ ──→ PAUSED ──→ 用户点继续 ──→ TRANSLATING
  ├── 断路器（5 批连续失败）──→ PAUSED（带错误提示 + 重试按钮）
  ├── 401 / 403 ──→ ERROR（全停，FAB 变红，弹出设置面板）
  ├── 429 限流 ──→ 降低并发 + 退避重试（最多 3 次）
  └── 全部完成 ──→ IDLE（FAB 显示 ✅，2s 后恢复可点击）

所有状态转换由 Content Script 端 StateManager 主控。

九、缓存与存储

┌── 内存层（最快，进程内）───────────────┐
│  Map<fingerprint, translation>          │  写入：立即
│  命中率最高的热数据                      │  读取：O(1)
└─────────────────────────────────────────┘
        │ 定时刷（每 5 秒 或 每 20 条）
        ▼
┌── chrome.storage.session（中间层）─────┐
│  crash recovery + 跨 SW 唤醒            │
│  Key: wt_cache_{tabId}                 │
│  上限：每 tab 最多 500 条 LRU 淘汰       │
└────────────────────────────────────────┘

chrome.storage.local：仅存用户配置（不存翻译内容）
为什么不用 IndexedDB？
IndexedDB 在 MV3 中由网页 origin 隔离 —— Content Script 运行在宿主页面 origin，存在数据泄露和命名冲突风险。chrome.storage.session 在扩展 origin 下安全隔离，且浏览器重启后自动清空，符合翻译缓存的隐私期望。

十、异常流程与容错设计

10.1 API 层异常

异常场景检测方式处理策略
超时 模型响应超过 30 秒 CS 端 AbortController 定时器 该批次标记失败，各段显示 ❌ 重试按钮；队列继续处理其他批次。CS 发送 CANCEL_BATCH 给 SW。
API Key 无效 / 余额不足 HTTP 401 / 403 全停，FAB → 🔴，弹出错误详情 + 设置面板入口。
限流 429 HTTP 429 + Retry-After 头 降低并发 + 指数退避（2^n 秒）；最多重试 3 次。
返回空 / 格式错乱 / 段数不匹配 parseBatchResponse 校验 整批视为失败（段数不匹配时），各段 fallback 原文显示，记录日志。
CORS 拦截 fetch 异常 由 Service Worker 代理请求，Content Script 不直接发请求，从根本上规避。

10.2 网络层异常

异常场景处理策略
网络中断（离线） 监听 navigator.onLine + online/offline 事件；暂停队列，FAB → 🌐⚠️；恢复后自动继续。
DNS 失败 / 不可达 2 次重试（1s → 3s），仍失败则标记该批失败，不影响其他批次。

10.3 页面层异常

异常场景处理策略
SPA 动态内容 MutationObserver（debounce 500ms）+ IntersectionObserver 双重覆盖；L1 DOM 标记 + L2 内容指纹去重。
页面无内容区 回退到 document.body；仍无 → Toast "未检测到可翻译内容"。
宿主 CSS 污染 Shadow DOM + CSS Reset；关键样式全部内联定义。
页面卸载 beforeunload → 优雅停止 + 缓存刷入 storage.session；下次访问相同 URL 秒级恢复。
原文动态修改 已翻译段落挂 MutationObserver → 标记 ⚠️ 过期 → 用户可点击刷新。
扩展更新（热更新） CS 初始化时检查 data-wt-done 标记，发现已有标记则跳过，避免重复翻译。

10.4 用户操作异常

异常场景处理策略
连续快速点击翻译 防抖 500ms；状态机确保单一翻译会话。
中途停止翻译 CS 端全局取消标记 + AbortController map 全部 abort；SW 收到 STOP_ALL 忽略后续请求。已完成保留，未完成保持原文。
未配置 API 预检查配置完整性（URL + Key + model 三者齐全），缺失则打开设置面板并高亮必填项。

10.5 存储层异常

异常场景处理策略
chrome.storage.local 写入失败 降级到 chrome.storage.session，Toast 提示用户。
storage.session 超 10MB 每 tab 缓存上限 500 条，LRU 淘汰。
QUOTA_BYTES 超限 捕获 chrome.runtime.lastError，提示用户清理。

十一、核心健壮性机制

11.1 重试与断路器

  • 单批失败 → 自动重试 2 次，退避 1s → 3s。
  • 429 限流 → 读取 Retry-After 头，或 2^n 秒退避（2s → 4s → 8s）。
  • 连续 5 批失败 → 断路器触发，自动暂停，FAB → ⏸️，弹出提示。

11.2 事务性保证

每个段落的翻译是独立原子操作。成功 → 插入译文（DOMPurify 净化后）；失败 → 保持原文。净化白名单仅允许 <b><i><em><strong><code><pre><br><span>，移除 script、on* 事件、javascript: URL。

11.3 输入校验

字段校验规则
API URL正则 /^https?:\/\/[\w\-]+(\.[\w\-]+)+.*$/；HTTP 给出安全警告需二次确认
API Key非空，长度 ≥ 8
模型名非空，长度 ≤ 100
并发批数整数 1–10
单批字符上限整数 500–5000

11.4 资源清理

  • 翻译停止/完成 → CS 端释放所有 AbortController、定时器、IntersectionObserver、MutationObserver。
  • 插件卸载（chrome.runtime.onSuspend）→ SW 清理进行中的 fetch。
  • 下载完成 → Data URL 无需手动 revoke；图片 Blob 在打包后立即释放。
  • FAB 拖拽事件 + Port 连接在页面卸载时移除。

      │     (内联: insertTranslation / 面板: port.postMessage)                   │
      │ 12. writeCache(fingerprints → translations) │                              │

      —— 取消场景 ——
      CS 端 abort(batchId) → 移除对应 AbortController
      SW 端收到 CANCEL_BATCH → 忽略该 batchId 的 API 响应，不 sendResponse

十三、安全与隐私设计

关注点设计策略
API Key 存储 chrome.storage.local（仅本地）；未来可选升级为 storage.session（重启清空，更安全）。
数据传输 强制 HTTPS；HTTP 地址保存时弹窗警告需二次确认。
XSS 防护 DOMPurify 白名单净化 + Shadow DOM 样式隔离双层防护。
权限最小化 activeTab + storage + downloads + scripting + sidePanel；不读浏览历史、cookies。
用户告知 设置面板底部固定隐私声明 + API 地址可信提示。
缓存安全 chrome.storage.session 浏览器重启自动清空；不持久化原文/译文到磁盘。

十四、悬浮按钮（FAB）交互设计

14.1 位置管理

  • 默认：右下角，距边缘 20px，z-index: 2147483647。
  • 长按拖拽：长按 300ms 进入拖拽模式，释放后位置存入 chrome.storage.local，跨页面复用。

十五、扩展性预留

  • 多语言：设置面板预留语言选择器，Prompt 按 {sourceLang}/{targetLang} 动态生成。
  • 多模型：Adapter 模式 —— buildRequest() + parseResponse()；内置 OpenAI-compatible 和 Anthropic 适配器。
  • 主题：Shadow DOM 内 CSS 变量，未来跟随 prefers-color-scheme 自动 dark/light。
  • 配置导入/导出：JSON 导出/导入（不含 API Key）。
  • 划词翻译：mouseup → 旁出按钮 → 复用 Adapter + SW 代理管道。
  • 流式翻译：stream: true 参数位预留；SW 通过 ReadableStream 逐 chunk → Port 推送。
